# YVR Bridge

**YVR 桥 · 面向 YVR 设备的 OpenXR 应用兼容与适配项目。**

YVR Bridge 旨在降低 XR 应用与 YVR 平台之间的兼容障碍，通过应用级兼容层处理交互配置、图层合成、纹理格式和运行时行为差异，让更多应用能够在 YVR 设备上正确显示与交互。

项目将实际移植过程中发现的问题、修复代码与验证记录整理为可复用的适配经验。当前发布版本以 YVR 2 上的首个成功案例为基础；其他应用、机型和固件需要分别适配与验证。

## 项目目标

- **连接应用与运行环境**：处理 XR 应用对输入配置、扩展及图层行为的不同预期。
- **保留正确的追踪与交互**：依据问题所在层修复兼容差异，避免通过伪造姿态或点击坐标掩盖渲染问题。
- **积累可复现的方案**：公开源码、构建部署步骤、诊断依据及回退方法。
- **记录真实兼容状态**：按设备、固件和应用版本记录结果，区分初始化成功与头显实际可用。

## 当前实现

当前兼容层采用原生 OpenXR 代理，位于应用与其既有加载器之间。它保留原加载器入口，将需要适配的调用交给兼容逻辑，其余调用转发给原实现。

```text
XR 应用
   │ OpenXR 调用
   ▼
YVR Bridge 应用级兼容层
   │ 按已验证规则处理输入、扩展和图层差异
   ▼
应用既有 OpenXR 加载器
   ▼
YVR 系统运行时与合成器
   ▼
头显显示与手柄交互
```

| 适配方向 | 当前已有实现 | 使用边界 |
| --- | --- | --- |
| 输入绑定 | 交互配置与部分按键路径映射 | 当前规则来自首个案例，其他应用需检查 action 与路径 |
| 扩展兼容 | 调整扩展枚举，触发应用已有的渲染回退 | 应用必须确实具备对应回退路径 |
| 投影方向 | 在图像释放前用 GPU 修正投影纹理方向 | 当前覆盖已验证的动态、全幅 GLES 2D 投影链 |
| 运行诊断 | 有限次数的姿态、交换链与兼容层日志 | 日志需结合头显实测判断 |
| 部署恢复 | 校验原库、备份、替换与回退脚本 | 依赖当前安装方式及 root 写入权限 |

这些是当前代码已实现的能力，具体启用条件仍与现有适配规则绑定。新增应用时需要重新分析，不能直接套用全部修复。

## 开始使用

### 1. 确认适配方案

先阅读对应案例的环境与限制，核对设备、固件、应用版本及原加载器。当前构建脚本锁定首个案例的原库 SHA-256；不同哈希会被拒绝。应用与固件版本由使用者另行核对。

需自行准备有权使用的原应用及加载器。当前方案要求原加载器已经能够选择并初始化 YVR 运行时。

### 2. 准备构建环境

当前已验证的本机构建环境为 Linux x86_64、Python 3.9+、Android NDK 27.2.12479018 和 OpenXR 头文件 1.0.34。构建命令在本源码目录执行：

```bash
python3 build.py \
  --original "/absolute/path/to/your/libopenxr_loader.so" \
  --ndk "/absolute/path/to/android-ndk/27.2.12479018" \
  --openxr-include "/absolute/path/to/OpenXR-SDK/include"
```

输出位于 build/，包括代理库、原库改名副本及哈希清单。当前适配器保留已验证原库的 56 个 OpenXR 导出。第三方原库及其改名副本不属于项目原创源码。

### 3. 检查与部署

先确认 adb 授权和目标设备，再使用当前案例的部署脚本。部署会停止应用，并要求 root 写入应用原生库目录：

```bash
adb devices
python3 deploy.py status --serial YOUR_ADB_SERIAL
python3 deploy.py deploy --serial YOUR_ADB_SERIAL
```

当前脚本默认目标为首个案例的包名；--package 参数仅改变目标包名，不会生成新的适配规则。脚本动态解析安装目录，检查哈希并保留原件备份。完整的备份位置、异常处理与部署条件见 [案例文档](docs/cases/virtual-desktop-yvr2.md#5-首次部署与检查)。

可选 Magisk 模块用于首个案例的启动属性误判，**会影响设备级属性，并需重启**。应根据案例判断是否需要，勿作为所有应用的通用前置步骤。

### 4. 验证与回退

在头显中检查画面方向、手柄姿态、菜单显示与命中位置，并测试转头、按键和场景切换。串流、网络、音频、性能等功能应另外验证。

```bash
adb -s YOUR_ADB_SERIAL logcat -s VDYVRInput overportOXR oxr_error oxr_logger
python3 deploy.py rollback --serial YOUR_ADB_SERIAL
```

回退脚本恢复原始加载器；可选属性模块需单独卸载并重启。安装、升级应用或更换固件后，应重新确认兼容状态。

## 如何适配其他应用

1. **建立原始基线**：记录设备、固件、应用版本、加载器与实际错误，保留可恢复的原件。
2. **定位差异层**：区分启动判断、输入配置、追踪数据、纹理分配、渲染与合成问题。
3. **定义最小修复**：明确触发条件和影响范围，保留其他应用行为与正确的追踪数据。
4. **实现可回退规则**：核对导出及 ABI，检查调用顺序、图像所有权与 OpenGL 状态。
5. **完成实际验证**：同时保留关键日志与头显实测结果，分别标注通过、失败和未测试项。
6. **提交案例记录**：说明构建部署方法、恢复步骤、已知限制及可复现的测试条件。

当前源码以单个案例为基线。多应用配置、独立适配规则与更多运行环境覆盖仍需要后续实现和验证。

## 已知限制与验证范围

- 当前运行验证集中在一个 YVR 2 应用/固件组合，不应推断其他组合自动兼容。
- GPU 方向修正针对动态、全幅的 GLES 2D 投影链；局部矩形、数组纹理、多 EGL 上下文、并发访问及交换链用途变化尚未覆盖。
- 新投影链首次识别前可能有一帧未修正，额外 GPU blit 的长期性能与功耗尚未测量。
- 日志中的 FBO 完整或初始化成功不能替代实际显示验证。
- 发布整理时已重新编译源码，并模拟验证便携脚本的状态、部署、备份、回退和未知库拒绝；便携脚本本轮未重新写入头显。此前用户实测对应已部署的同一 v5 兼容层源码。
