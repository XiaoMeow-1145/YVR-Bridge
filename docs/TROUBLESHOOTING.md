# 问题处理与故障排查

本文档用于记录 YVR Bridge 在构建、部署和运行过程中遇到的问题、排查方向、已知解决办法及尚未解决的事项。

## 1. 提交问题前

请尽量提供以下信息：

- 头显型号
- 系统固件版本
- 应用名称及版本
- YVR Bridge 版本或补丁版本
- 问题发生阶段
- 完整错误提示或相关日志
- 是否能够稳定复现
- 最近一次正常运行时的环境

请避免只提供“无法启动”或“画面异常”等无法定位问题的描述。

## 2. 按现象排查

### 应用无法启动

1. 确认 APK 和原生库 ABI 与设备一致。
2. 检查补丁文件是否正确部署。
3. 对比启用补丁前后的启动日志。
4. 确认是否在加载动态库或初始化 OpenXR 时失败。
5. 尝试回退补丁，确认问题是否由本次修改引入。

### OpenXR 初始化失败

检查应用请求的 Runtime、扩展和 API 调用，并确认目标设备 Runtime 是否提供对应能力。不要仅凭扩展名称相同就认定行为完全一致。

### 进入应用但没有正确显示

分别检查 XR 会话是否建立、交换链是否创建、图层是否提交，以及投影和纹理格式是否符合目标 Runtime 的要求。

### 控制器或交互异常

确认应用使用的输入路径、动作集、绑定配置及目标设备实际提供的输入能力。区分输入未识别、绑定缺失和应用自身交互逻辑问题。

### 版本或设备识别问题

先定位应用执行检查的位置，并确认该检查是否影响功能、服务或账号流程。仅在明确了解影响范围后，才考虑采用应用级兼容处理。

### 性能或稳定性问题

记录帧率、卡顿发生场景、运行时长及 CPU/GPU 负载。区分应用自身负载、运行时开销、录制或串流开销，以及补丁引入的额外处理。

## 4. 已解决与未解决问题

请将每个问题记录为独立条目，并注明：

- 首次发现的版本或环境
- 问题原因（已确认时填写）
- 解决方案
- 验证设备及版本
- 是否仍存在限制

不要把推测原因写成已确认结论，也不要把单次成功写成稳定解决。

## 5. 回退建议

如果启用补丁后出现新的异常：

1. 停止继续叠加其他补丁。
2. 使用备份恢复原始文件或禁用对应模块。
3. 确认应用是否恢复原状。
4. 保存失败日志和补丁版本信息。
5. 将复现步骤提交到项目问题记录中。
