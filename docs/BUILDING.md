# DIY 构建与新增应用

本文档面向希望自行构建 YVR Bridge、添加应用适配或开发自定义补丁的开发者。

> 注意：具体构建命令、依赖版本、配置字段和部署参数应以仓库当前源码及构建脚本为准。本文不虚构尚未确认的命令或配置格式。

## 1. 开始之前

建议先熟悉：

- Android 原生开发与 arm64 动态库基础
- OpenXR Loader、Runtime 和扩展的基本关系
- APK 内原生库的目录结构
- 目标应用的版本、ABI 和运行环境

同时准备目标设备、可恢复的原始文件，以及用于查看应用日志的调试环境。

## 2. 获取项目

从 GitHub 获取项目源码：

[https://github.com/XiaoMeow-1145/YVR-Bridge](https://github.com/XiaoMeow-1145/YVR-Bridge)

克隆后先阅读仓库根目录 README、构建脚本及现有案例，不要直接假设其他版本的构建参数仍然适用。

## 3. 构建现有项目

建议按以下顺序操作：

1. 检查构建环境和依赖是否满足项目要求。
2. 阅读构建脚本，确认输入文件、配置项和输出位置。
3. 按项目当前提供的构建流程执行构建。
4. 检查生成文件的 ABI、文件名和依赖关系。
5. 在测试设备上部署，并保留部署前的备份。
6. 启动目标应用，收集日志并验证功能。

## 4. 为新应用添加补丁

### 第一步：确认应用信息

记录应用名称、版本、来源平台、APK 版本及 ABI。确认目标设备和系统版本。

### 第二步：复现问题

先在不启用新补丁的情况下复现问题，记录错误提示、日志和发生阶段。尽量将问题缩小到初始化、输入、渲染或平台检查等具体环节。

### 第三步：确定适配位置

根据证据判断问题属于 OpenXR 接口差异、原生库行为、设备识别、输入配置还是显示链路。避免在原因不明时同时修改多个位置。

### 第四步：编写独立补丁

尽量将新应用的专用逻辑独立组织，并注明适用版本和启用条件。不要让单个应用的特殊处理默认影响其他应用。

### 第五步：构建与验证

构建后先检查产物，再部署到测试设备。逐项验证启动、XR 会话、头显显示、控制器输入、菜单交互及长时间运行情况。

### 第六步：记录结果

将设备型号、固件版本、应用版本、补丁版本、验证结果和已知问题补充到 [COMPATIBILITY.md](COMPATIBILITY.md)。

## 5. 提交补丁时建议提供

- 应用名称与版本
- 目标设备与系统版本
- 问题复现步骤
- 原始日志或错误信息
- 补丁修改范围与实现目的
- 构建方式及产物信息
- 已通过和未通过的测试项目
- 回退方式

## 6. 安全与回退

修改应用原生库或部署系统级模块前，应备份原始文件。优先使用可撤销的部署方式，并确保设备能够恢复。不要在未经验证的情况下覆盖关键系统组件。
